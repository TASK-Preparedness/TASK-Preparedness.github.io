Support & contribute

T.A.S.K. is an experimental alpha. There is no official support desk and no project email address: everything goes through GitHub.

Report a problem or a test result

Please use the issue templates (blank issues are turned off, because the templates ask for the details that make a report usable).

Kind of reportWhere
Bug, crash, wrong behaviorGitHub issue → Bug report
I tried a test or an install (pass, fail, skip or blocked)GitHub issue → Volunteer test report
My board, radio, GPS or SDRGitHub issue → Hardware compatibility report
Packages, checksums or detection failedGitHub issue → Installation problem
A feature ideaGitHub issue → Feature request
Security, unexpected transmit, or a privilege issuePrivate report only — see below

What to include

Run these one at a time and paste the output (redact anything personal):

cat /proc/device-tree/model; echo; grep Revision /proc/cpuinfo; dpkg --print-architecture; cat /etc/os-release
dpkg-query -W -f='${Package}\t${Version}\t${Architecture}\n' 'task-*' python3-task-comms

Also say what you were trying to do, what happened, what you expected, and include redacted logs. Remove callsigns, locations, GPS tracks, message text, device serial numbers, passwords and home-directory paths before posting.

What we cannot do yet: remote access to your Pi (do not offer SSH to a production or working system), or promise a fix date.

Report a security or RF-safety problem

Do not open a public issue, discussion or pull request for security problems. There is no security email address — do not send reports to a personal mailbox.

Use GitHub’s private vulnerability reporting: go to the repository’s Security → Report a vulnerability, or open the form directly:

Report a vulnerability privatelyRead the security policy

Include the affected module and version, hardware, steps to reproduce and the impact. What counts: anything that could transmit on a radio without explicit operator action; bypassing device ownership, accounts or session checks; code execution, privilege escalation or path traversal (for example in the ZIM/EPUB reader); leaking callsigns, locations, messages or credentials; installer behavior that changes system configuration unexpectedly. Only the current pre-release and the main branch receive fixes.

Contribute

Every contribution is welcome: testing on your hardware, bug reports, documentation, translations and code. Say clearly what you tested, on what hardware, and what you did not test.

Ground rules

  • Be kind: read the Code of Conduct.
  • Never commit secrets, callsign databases, personal data, device serial numbers or your own config files.
  • Never add code that transmits without an explicit operator action, starts services automatically, or flashes firmware without explicit confirmation.
  • Report results honestly. Don’t claim Windows support or physical-Pi validation unless it has been done.

Licensing of contributions

  • Inbound = outbound: you contribute under GPL-3.0-or-later and keep your copyright. No CLA.
  • Sign off every commit with the Developer Certificate of Origin (git commit -s).
  • Add the SPDX license header to new source files, and list third-party code in THIRD_PARTY_NOTICES.md.

Development setup, running tests, building packages and the pull request checklist are in CONTRIBUTING.md. Open an issue first for anything large. Questions about trademark use go in a GitHub issue (see the trademark summary).

Support the project (optional)

Financial contributions are entirely optional. T.A.S.K. stays free software under the GPL, and stays free of charge for essential preparedness features. No software features are, or will be, restricted based on financial contributions. Contributions support development time, equipment, testing, maintenance and future improvements.
